# Interest modes and weighted submodes

[interest-modes.json](../../interest-modes.json) is the single source of truth for mode definitions, submode texts, definitions and weights, submode embeddings, and calculated mode vectors.

## Structure

```json
{
  "embedding_model": {
    "name": "text-embedding-3-small",
    "version": "1",
    "dimensions": 1536
  },
  "modes": {
    "discuss": {
      "definition": "Talking about, debating or sharing ideas",
      "vector": null,
      "submodes": [
        {
          "text": "discuss",
          "definition": "Talking with others to exchange ideas.",
          "weight": 0.1,
          "vector": null
        },
        {
          "text": "sharing the latest news on a subject",
          "definition": "Exchanging recent news about a topic.",
          "weight": 1,
          "vector": null
        }
      ]
    }
  }
}
```

- A mode's `definition` is display text, independent of its submodes.
- A mode's `vector` is generated by averaging; it is not embedded directly.
- Submodes are array entries owned by their parent; they need no IDs.
- Each mode includes its exact label with a low weight of `0.1`.
- Each submode's `definition` is the input used to generate its vector.
- Generated numeric vectors are kept on one line to make the editable fields easy to locate.

## Embedding refresh (internet required for uncached texts)

### Modes -> Edit

Open **Modes -> Edit** to expand a mode and edit its definition, submode texts, definitions, and weights. Contribution percentages show each weight's share of the total. Uncheck Enabled to set a weight to zero; re-enable to restore its previous weight within the current editing session. Add or delete submodes as needed.

The info button contains editing and scoring guidance. The complete content area scrolls together; text fields grow to fit their contents in the compact table.

Select a **Test keyword** to compare raw cosine scores against individual submodes, the saved mode vector, and a preview average using current weights. Preview scores do not save changes. Numeric vectors remain hidden.

Use the top bar's **Save** to save all pending mode and identity-file edits, including edits from other pages. Mode drafts survive menu navigation. **Reload** discards all pending edits after confirmation, and closing the browser warns about unsaved changes. Concurrent mode-file changes require reloading instead of silently overwriting them.

**View unsaved** opens a panel grouped by file, listing changed fields with before/after values compared with the last load or successful save. Added and removed values are marked `(absent)`; large embedding arrays are summarised rather than displaying thousands of numbers. This is a browser-draft comparison, not a Git diff. If a save partially fails, successfully saved files disappear from the panel and remaining edits stay pending.

After saving weight changes or deletions, choose **Recalculate averages (offline)**. Text changes require **Refresh embeddings**, which automatically calculates and persists mode averages after refreshing. Refresh uses the existing embedding job, which also verifies preference and kind embeddings; save or reload all pending edits first to avoid stale identity drafts overwriting refreshed vectors. Uncached texts require internet and Azure credentials. Recalculation and refresh remain separate from Save.

Open **Embeddings -> Update** in QFFViz and run the job. It verifies all embedding inputs against the cache, refreshes stale submode embeddings, then calculates and writes all mode averages into the same file. This also happens on cache-only refreshes. Dry runs do neither and change no files.

When editing a submode's text or definition directly, clear its `vector` and parent `vector` to `null`. The editor invalidates changed submodes automatically. The local embedding cache is used to verify definitions and vectors; missing or mismatched cache entries require a refresh before offline averaging.

## Modes -> 3D: inspecting outliers

Open **Modes -> 3D** for a 3D view with **UMAP** selected initially; **PCA** is also available. Triangles represent mode averages and circles represent submodes, sharing their parent's colour. All valid vectors start visible, including zero-weight candidates (smaller circles). Filtering does not refit the projection, so points stay in the same positions.

Expand the collapsible **Filters** section for Mode, dependent Submode choices and quick search. Choosing a mode limits the submode choices; choosing a submode retains its parent for comparison. These filters combine with AG Grid column filters. **Clear filters** resets all filters, including hidden table filters. The filtered point count remains visible.

The **Show data** checkbox starts unchecked. When checked, an AG Grid table appears below the plot; scroll the whole page down to the table or up to the plot. Column text/number filters control visible Plotly points even after hiding the table or collapsing Filters. This uses AG Grid Community, not Enterprise Set Filters or its Filters Tool Panel.

Click a Plotly point to select its row, or Ctrl-click/Command-click to toggle additional selections. Grid row clicks and selection checkboxes highlight the corresponding plot points. Selections remain when filtered out and become visible again when filters are cleared. Selection does not edit saved mode data.

The view derives current weighted averages offline without saving. Missing or outdated saved averages are labelled as previews. Missing, stale, wrong-dimensional or zero-length vectors are reported rather than projected. Refresh those embeddings in **Edit**; use **Recalculate averages** to persist parent averages.

UMAP preserves neighbourhoods imperfectly; apparent separation does not prove a submode is wrong. PCA shows the fraction of variance retained in three axes.

## Modes -> Heatmap: full-dimensional alignment

Open the separate **Modes -> Heatmap** page to compare submodes with mode averages using all original dimensions. It has its own mode/submode visibility controls and an accompanying diagnostic alignment table, but no 3D plot or projection selector.

- **Parent cosine**: similarity to the weighted parent, including the submode itself.
- **Sibling cosine**: similarity to the weighted average of the other submodes, excluding itself. This avoids a high-weight outlier pulling its own reference toward itself.
- **Rival**: the most similar other mode average.
- **Gap**: sibling cosine minus rival cosine; negative values suggest ambiguity worth reviewing, not automatic rejection.

The table sorts weakest sibling alignment first. Scores for missing references are unavailable, not zero. Comparisons use vectors embedded from each submode's contextual definition.

### Evaluating alternative wording

For a suspect `attend` submode of Visit, add `attend gallery`, `attend venue`, or more descriptive alternatives in **Edit** as separate submodes at **weight zero**. Save and refresh embeddings, then compare their sibling cosines, rival gaps and **Test keyword** scores. Weight-zero candidates do not change the parent average. Keep representative topic-only and activity-led test keywords across all modes: a candidate that fits one example better may over-specialise or blur another mode.

Other useful analyses beyond 3D:

- A full pairwise cosine matrix exposes whether a submode agrees with several siblings or only one; hierarchical clustering of cosine distances can show cross-mode families without a 3D layout.
- Nearest-neighbour rankings in the original dimensions can reveal alternative modes/submodes competing with the intended interpretation.
- A cosine-distance-to-siblings versus rival-gap plot highlights weak alignment and ambiguity directly, rather than relying on projected distances.
- Compare 2D/3D UMAP across neighbour counts/seeds and PCA axes beyond the first three. Only investigate outliers that are also supported by original-dimensional scores.
- Evaluate candidates on a fixed labelled keyword set and inspect confusion between modes. This tests their intended use, not merely whether a reference clusters near its siblings.

There is no universal cosine cut-off for a good submode. Use within-mode comparisons and held-out keyword performance; do not automatically remove a useful submode just because UMAP separates it.

### Embedding input strategy

Submodes are embedded using their trimmed `definition`, written in the context of their parent mode. Identical definitions share the same cache input and vector; identical labels with different definitions do not.

If a bare term is ambiguous, add longer descriptions as separate submodes and refresh. Compare candidates on the same held-out topic-only and activity-led keyword set. Measure mode classification, confusion with rivals and keyword ranking, not merely tighter UMAP clusters. A contextual phrase can over-specialise toward its example topic.

Refresh verifies definition inputs against the cache and automatically recalculates every parent average. The editor and offline recalculation use the local cache to verify vectors; refresh is required if the cache is missing.

## Averaging (offline)

From QFFViz:

```powershell
npm run calculate-mode-vectors
```

Or from QFF:

```powershell
node calculate-mode-vectors.ts
```

The script updates only the parent mode vectors, preserving definitions, texts, weights, and submode vectors.

For each dimension: `mode = sum(weight * submode vector) / sum(weights)`.

Weights must be finite and nonnegative, with a positive total per mode. Zero weight excludes a submode from the average. Missing or stale positive-weight vectors fail explicitly rather than silently producing a partial average.

Changing weights, deleting submodes, or reordering entries needs no new embeddings. Recalculate and reload the UI. Adding or changing submode text or definition requires embedding refresh before recalculation.

The API returns each mode's definition and vector. It omits unverified mode vectors from scoring until refreshed or recalculated; the embedding status page explains what action is needed.
