# Interest modes and weighted submodes

[interest-modes.json](../../interest-modes.json) is the single source of truth for mode descriptions, submode texts and weights, submode embeddings, and calculated mode vectors.

## Structure

```json
{
  "embedding_model": {
    "name": "text-embedding-3-small",
    "version": "1",
    "dimensions": 1536
  },
  "modes": {
    "discuss": {
      "description": "Talking about, debating or sharing ideas",
      "vector": null,
      "submodes": [
        {
          "text": "discuss",
          "weight": 0.1,
          "vector": null,
          "embeddedText": null
        },
        {
          "text": "sharing the latest news on a subject",
          "weight": 1,
          "vector": null,
          "embeddedText": null
        }
      ]
    }
  }
}
```

- A mode's `description` is display text, independent of its submodes.
- A mode's `vector` is generated by averaging; it is not embedded directly.
- Submodes are array entries owned by their parent; they need no IDs.
- Each mode includes its exact label with a low weight of `0.1`.
- `embeddedText` records the exact input that produced a submode vector: `<mode>: <text>`. This preserves the inputs and cached vectors used before consolidation.
- Generated numeric vectors are kept on one line to make the editable fields easy to locate.

## Embedding refresh (internet required for uncached texts)

Open **Embeddings -> Update** in QFFViz and run the job. It verifies all embedding inputs against the cache, refreshes stale submode embeddings, and writes them into the same file. It does not calculate mode averages.

When editing a submode's text, clear its `vector` and `embeddedText` to `null`, and clear the parent `vector`. Both scripts also detect edits made outside this workflow using `embeddedText`; stale vectors are never used for averaging.

## Averaging (offline)

From QFFViz:

```powershell
npm run calculate-mode-vectors
```

Or from QFF:

```powershell
node calculate-mode-vectors.ts
```

The script updates only the parent mode vectors, preserving descriptions, texts, weights, submode vectors, and embedding provenance.

For each dimension: `mode = sum(weight * submode vector) / sum(weights)`.

Weights must be finite and nonnegative, with a positive total per mode. Zero weight excludes a submode from the average. Missing or stale positive-weight vectors fail explicitly rather than silently producing a partial average.

Changing weights, deleting submodes, or reordering entries needs no new embeddings. Recalculate and reload the UI. Adding or changing submode text requires embedding refresh before recalculation.

The API retains its existing mode description/vector response shape. It omits stale mode vectors from scoring until refreshed or recalculated; the embedding status page explains what action is needed.
